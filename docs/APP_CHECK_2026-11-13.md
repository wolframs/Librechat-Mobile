# App check on the emulator, 13 November 2026

A dated record: what was run for real on the new base (upstream 2026.11.1 plus the empty `:fork`
module), signed in as the test account against the owner's LibreChat, and what it showed. Findings
that become work move to `docs/FORK_FEATURE_LEDGER.md` (fork features) or go upstream; this file is
not updated afterwards.

Setup: Pixel 7 emulator, Android 17, server on the LAN address over plain HTTP. Models: `Surplus` /
`deepseek-v4.1-flash` and native `anthropic` / `claude-haiku-4-5`.

## What was run for real

| Thing | Result |
|---|---|
| Sign-in, new chat, streaming reply | Works. |
| `web` server (read one address) | Works: one tool call, correct answer. |
| `optmem` memory | Works: one note saved. It ran although the app showed the server as off (see B5). |
| `imager` | Works: one image for $0.01, shown in the thread. |
| Web search (the built-in one, through SearXNG) | Works: "Searched the web", a source pill. |
| A PDF from the server's file list, on native Anthropic | Works: attached, read, answered. |
| `audio-ears` | Its list tool was called and answered. Listening was not run: no audio could be attached (see "Not run"). |
| `code-agent` | Connects and lists 7 tools. No job was started, on purpose. |
| Upgrade from the old fork build | Works, see the ledger. |

Keys: the test account's stored Anthropic and OpenRouter records were unusable. Both were replaced
with copies of the owner's records (his go-ahead, same day). Anthropic then worked. OpenRouter
answered `401 API key expired`: the owner's stored OpenRouter key has expired; his last OpenRouter
chat was on 10 August. Until a new key is entered in LibreChat, OpenRouter cannot be tested, and its
model list falls back to the four defaults from the yaml.

## Bugs

- **B1. The first message of a new chat ignores the MCP servers that are switched on.** New chat on
  `anthropic`, `imager`, `web` and `audio-ears` checked ("3 of 5 on"): on the first message the model
  had only the server's default-on tools (web, memory) and said it had no audio tool. On the second
  message all of them were there. Seen once; the cause is not looked into yet.
- **B2. A raw error object as the reply.** A key record that exists but cannot be used gives
  `{"type":"no_user_key"}` in the red box. It should say that the provider needs a key and offer the
  key screen.
- **B3. A chat whose first message failed is missing from the drawer** and keeps the title "New
  Chat", although the server has it with ten messages.
- **B4. Two status lines for one server.** The "+" sheet said "Not connected" for servers that had
  just run a tool; the MCP servers page said "Connected" a minute later.
- **B5. Default-on servers look off and cannot be switched off.** The backend fork switches `optmem`
  and `web` on for every chat (`defaultOn`) unless the chat opts out (`mcpOff`). The app shows both
  unchecked ("0 of 5 on") while they run, and has no way to send the opt-out. This is a gap against
  the backend fork, not an upstream bug.
- **B6. A failed share into the app shows internals**: the message names the package and a content
  address, and the chip is titled with the file's id ("46"). The failure itself came from how the
  test delivered the file.

## Improvements worth making

1. **Tool calls by their plain name.** The thread shows `fetch_mcp_web` and
   `generate_image_mcp_imager`. Show the server and the tool ("web · fetch"), with the server's mark.
2. **A new chat should open on a model that can answer.** A fresh install opened on `gpt-5.5`,
   "Needs your key". Skip providers without a key when choosing the first model.
3. **Model picker order.** Four providers without a key (OpenAI, Google, Assistants, xAI) fill the
   top of the list. Put usable providers first and fold the rest into one "add a provider" row.
4. **Text under the status bar.** A scrolled thread shows through behind the clock and the floating
   header buttons and collides with them. A short fade at the top would fix the look.
5. **MCP server cards** have an empty line under the name; the tool names or a description fit there.
6. **Titles for chats that start with a file** come out as the title model's complaint ("I notice
   the conversation appears incomplete…"). That is the server's title step, not the app.

## Not run

  the web client does since 11 November, is therefore open.
- Any chat on `Surplus (Claude)` or OpenRouter, a code-agent job, anything on iOS.
